# MYN: current features and development rules

This is the maintained reference for source version **1.0**, deployed at `D:\MYN`. Verify behavior against current code and tests.

## Documentation and language

Update this document with every change to functionality, help, data structures, startup or maintenance. Delete superseded text and replace the relevant section in place. Never append patch notes, dated entries, version chapters or contradictory explanations. Replace verification results with current evidence; detailed history belongs in separate backups and logs. Give each feature one primary explanation.

UI labels, built-in messages, help, prompts, comments and documentation use English. Retain Chinese/Japanese input patterns, phonetic wake spellings and language test fixtures needed for recognition. Preserve original messages, names, personal files and saved data. Input rules and legacy markers are not display labels. Generated conversation follows the user's language and instructions.

Distinguish isolated tests, deployment checks and actual external-service/device validation. Mock models and synthetic audio do not establish live service or recognition quality.

## Startup and deployment

The desktop `MYN.lnk` launches `C:\Program Files\Python39\pythonw.exe D:\MYN\src\myn_gui.py`, working directory `D:\MYN`, without a console. Tk owns the main window; an independent WebView2 child renders the preferred UI using JSON messages, with Tk fallback. Network, model and speech work must not block the event loop.

`local-agent` is the legacy background-task environment. `local-tts` retains the shared Python 3.12 speech environment; `local-stt` contains Whisper and wake recognition. The Qwen3-TTS synthesis weights were removed at the user's request. ElevenLabs is the only selectable speech output provider. Legacy local-voice fields and adapter code remain for backup compatibility, but saved/restored settings select ElevenLabs and no local synthesis weights are installed. No local chat model is bundled: Qwen chat weights, Ollama runtime and old ensure/start/stop Ollama launchers were removed. The optional chat adapter never installs, downloads, starts, probes or selects a model automatically. Qwen3-TTS is separate speech synthesis.

The current Windows x64 installer includes a private Python 3.9 desktop runtime, separate Python 3.12 speech and agent runtimes, pinned dependencies, Git/Bash and wake-recognition models. Setup downloads the pinned PyTorch wheel and Whisper weights from their official sources, checks SHA-256 before installation, resumes interrupted downloads and verifies imports before allowing launch. The optional local synthesis model is never downloaded. Verified temporary downloads are deleted after installation; incomplete downloads remain retryable. The component receipt limits uninstall to unchanged installed files and preserves modified/unknown files. Internet access and approximately 14 GB of free installation space are required. `MYN.exe` starts the editable source using the private desktop interpreter; it does not modify system Python or PATH. First startup offers local full-backup import before any model/API configuration. Existing databases skip this welcome screen. Passwords stay in local dialogs, restores verify archives and preserve prior data, and old backups with local speech settings use ElevenLabs. WebView2 is detected and installed from Microsoft when missing (internet required). The installer defaults to the current user's Programs folder and creates a desktop shortcut. It refuses active/linked install locations, backs up existing program files before upgrades, and never runs legacy cleanup or removes personal data/unknown files on uninstall. The build payload is an explicit allowlist of public code, package files and models; never package existing user environments wholesale, API keys, personal libraries or Git credentials. GPU drivers and device permissions remain Windows responsibilities.

Historical `versions/0.13.1`, installers and backups are not current entry points. Do not run old uninstallers or `maintenance/cleanup_legacy.ps1` against the source deployment. Preserve old backups. Build an EXE installer only on an explicit user request; routine work modifies and verifies source.

## User features

### Conversation and interface

The desktop shortcut and both Tk/WebView2 window surfaces use `src/assets/myn-symbol.ico`: the standalone black MN monogram on transparency, with no backing plate, frame, shadow or metallic shading. Gaps between strokes remain transparent, and the source PNG is `src/assets/myn-symbol.png`. All nine ICO sizes from 16 to 256 pixels retain alpha transparency. `app_icon.py` applies the shared Windows identity and window icons; the desktop shortcut points directly to the ICO. Replacing artwork does not rebuild an installer.

Claude Opus 5.5 is the fixed main model. Ordinary messages are saved verbatim before routing; substantive work receives deeper reasoning, longer context and more tool rounds. Replies stream, with long text, images, screen content and annotations in the main reader. Time, recent conversation, profile and preferences supply context.

The core's left arc contains Agents, Expenses, music and keyboard. An alarm entry appears for alarms within 24 hours; WebView2 also has an equalizer entry. Main/small cores share positioning and scale. Panels stay inside the main window and the small core returns to the main view. Reduced motion remains supported.

Agents is one scrolling voice/device/API-key page. No gear menu or separate memory, backup, profile, evolution or task settings pages remain; manage those conversationally and display results in the existing reader. Keyboard opens input; Esc collapses it. `core/chat.py:HELP` owns current help.

### Originals, memory, profile and preferences

Archive ordinary input before replying, then extract memories by scene. Compatibility commands remain in conversation history but bypass the sent_messages extraction queue. Credentials use masked dedicated settings, never chat archives.

Facts retain source quotations/timestamps. Inferences are separate and excluded from factual retrieval by default. Message time is not event time; plans or guesses do not prove completion. Profiles summarize traits, retain revisions and prioritize corrections, avoiding timestamped quotation logs. Preferences apply by scene and retain feedback, examples, history and effectiveness. One-time instructions do not automatically become permanent rules.

Natural queries cover originals, active memories, trash, profile and preferences with ranges, pagination and source details. Memory edits, category/type changes, trash and restoration require exact target reading, preview, actual confirmation and fresh-state verification. No unattended edits, arbitrary SQL, bulk deletion or permanent memory deletion. Keep compatibility commands `recent`, `today`, `week`, `month`, `category`, `trash`. Do not restore retired standalone search/semantic/summary/stats or Brain/CMD HUD. Conversational web search remains separate.

### Speech and quiet scenes

The microphone stays available for wake detection and existing archival, but hands-free conversation opens only after a fresh exact configured/learned wake phrase is recognized before fuzzy normalization. Say **Hey, Mine**. Acoustic/streaming matches and sound-alikes remain candidates, never authorization. Proactive reports, evolution invitations, pending reviews, ringing alarms, startup speech and interruption during MYN output cannot open a session. Holding right Ctrl or the microphone button sends one explicit request without opening hands-free chat unless it includes an exact wake phrase.

Inside a woken session, every substantive utterance passes addressing/scene judgment before any reply, local command or tool action, including the first request with the wake phrase, immediate followups and interruptions. Reuse the checked scene result in the reply rather than billing a duplicate classification. Clear speech to someone else or an explicit farewell closes the session; an addressed farewell can receive one final reply. Ambiguous speech and classifier failures stay quiet and do not refresh the timer. After 30 seconds without an exchange, return to wake-only mode; an ongoing voice reply and its playback keep the exchange alive. Closing clears automatic voice queues and invalidates late judgment callbacks; re-waking cannot revive old captures. Explicit button requests remain individual deliberate requests.

An exact spoken wake plays a locally generated 180 ms two-note chime through the selected voice output and volume, replacing the fixed spoken wake acknowledgement. It works for a bare wake and a wake followed by a request, even while a response is being prepared or automatic reading is off. A 1.5-second debounce prevents duplicate cues. Uncertain sound-alikes/acoustic candidates and singing remain silent. The cue uses a separate non-forced SDL channel, does not replace queued speech/music, and is not treated as spoken conversation. Device failure preserves the listening window without a popup or provider fallback. No model, speech synthesis or saved audio file is needed.

Whisper large-v3-turbo runs in a separate Python 3.12 process. The installer resolves `runtime/speech/python.exe`; a source installation keeps `local-tts/.venv`. CUDA remains the preferred device. A fresh system without a usable CUDA driver uses CPU with the same model and reports the slower device honestly. Preserve Chinese/English/Japanese recognition, pauses, echo filtering, interruption and device selection. Output uses ElevenLabs with the saved voice, model, speed and output device. No local synthesis model or automatic provider fallback is installed. Long replies read the opening unless full reading is requested. New turns and interruptions invalidate old audio and late synthesis.

Startup speech waits for the opening animation with a bounded 25-second fallback. The one-time opening greeting uses the startup purpose: a saved idle scene permits it even when an earlier classification remains pending. This does not clear or rewrite that state or authorize background notifications/restarts; sleep, study, singing and media playback still suppress the greeting. A conversation begun during launch supersedes it. Development-completion speech keeps the stricter proactive policy; when blocked in idle mode, the ordinary greeting remains eligible. Startup distinguishes requested synthesis from actual player start. A network/transient-service failure before any audio may retry once after 1.5 seconds, only while the same request remains current, automatic reading is enabled, and the user has not started talking or entered a quiet scene. Playback/device/authentication failures and failures after audio starts are reported in the chat without repeated speech. Startup outcome codes are persisted in voice diagnostics without speech text or service-response bodies.

Sleep, study, singing and nearby conversations reduce interruptions while direct requests remain available. In sleep, replies to the user's own addressed words (the good-night answer and later direct questions) are still read aloud; only proactive/scheduled speech stays silent. The once-per-night bedtime calendar briefing is read after the spoken good-night reply without cutting it off. Singing still mutes replies. Pitch/activity is a hint, not proof of singing or speaker identity; lyrics are not user facts. Quiet scenes defer proactive reports, speech and automatic restarts; alarms retain their independent exception. Spectrum display does not cause extra audio retention/uploads.

The wake-only rule applies in every scene, including sleep and alarms. Courtesy transcripts and other unrelated words before a wake remain unconfirmed without triggering a reply or addressing model. Preserve original archived captures, echo filtering and singing suppression. Entering sleep invalidates older callbacks; waking explicitly while already asleep still permits addressed conversation and spoken answers. Read-only voice inspection does not repeatedly announce an unchanged sleep scene. Diagnostics record numeric routing/capture metadata, never transcript/audio content. Addressing is a contextual model judgment, not speaker identification or a guarantee against ASR errors.

The core shows measured microphone and WASAPI loopback spectra across 128 bands. Reuse microphone capture; without spectra use only actual volume, never fabricated peaks. Clear stale/disconnected data, release devices on close and do not alter Windows default routing.

### Media and audio console

Music, Audio, Video and Movies share a local library with shuffle, lyrics, playback and resume. Scrolling is independent and navigation does not stop playback. The music alarm button sets a default sound without creating an alarm. Alarm volume is independent of music volume/mute. New alarms inherit the current default unless specified; an explicit empty sound uses speech. Changing defaults does not modify existing alarms.

The console provides six-band music/microphone EQ, gain, limiting, pitch, robot and telephone effects. Only music/audio use its media processing chain; video, movies, MYN speech and alarms do not. Microphone processing, monitoring and virtual sending require activation and do not resume automatically after restart. STT keeps its original input. Never report successful sending to a missing device. VB-CABLE is not installed; cross-app routing requires a separately installed/selected virtual device. Local EQ and monitoring work independently.

### Calendar, alarms, tasks and reports

Natural language manages MYN's calendar, reminders, alarms, countdowns and scheduled tasks in Asia/Tokyo time. Alarms and ordinary events/reminders have separate persistence/presentation to prevent duplicates. Due, finished, cancelled and recovered states follow their records. Confirm calendar deletion and sensitive scheduled actions at task creation.

Background tasks use Claude Agent SDK with progress/cancellation. Default per-task budget is 0 (unlimited), adjustable in chat. Both Bash and Windows PowerShell use the command policy. Self-edit commands are checked before execution, including auto-approved tools, and dependency installation is refused; planning remains read-only. These application checks are not an operating-system sandbox. Evolution points support review, discussion, adoption and manual completion. Adopted plans authorize automatic backup, deployment and idle restart after verification; unadopted suggestions cannot enable themselves.

Self-development must reproduce the failure, inspect callers and delayed callbacks, and test opposite cases. The protected host test runner collects executed test IDs, counts, skips and failures. Missing/empty execution evidence, infrastructure failures, removed/renamed tests and newly skipped existing tests block acceptance. Existing baseline failures remain visible rather than being described as all tests passing. Evolution records expose verification counts and distinguish them from unperformed live-audio checks. The copy includes protected tools/dev_finish.py for test imports only; never execute the completion hook from a self-edit copy. Tests cannot prove arbitrary code safe or substitute for real device checks.

An adopted self-improvement queues a read-only cost receipt. After startup confirmation it shows success, total recorded cost, model calls, planning/build/retry stages, verification and restart status; failure or rollback shows the corresponding result. Installation alone does not count as successful startup. Dismissing the receipt clears its persisted pending flag, so routine restarts do not repeat it; a newer attempt cannot be dismissed by an older receipt. The receipt uses the current point's recorded costs including planning and retries and never speaks or requests another approval. It uses the main WebView2 dialog with a Tk fallback.

Reports draw evidence from originals, preferences, profiles and development changes. They support subscriptions, pause/resume/cancel, deferral and paginated details. Reports differ from alarms and scheduled messages. Clarify ambiguous schedules, prepare only the latest missed report, defer invitations during quiet scenes and avoid repeated interruptions.

### Web, permissions, backups and expenses

The replaceable `web_tools` layer defaults to official Claude search with user-managed limits. Screen/images, windows, shortcuts, volume, media keys, URLs and system settings use existing tools/permissions. File reading requires specific folder grants. New permissions, folder grants and confirmation-policy changes require actual confirmation. Chat claims do not establish consent. Chat tools cannot delete files or run arbitrary commands; background work uses separate risk checks.

Full backup requests open local file/password dialogs. AES-256-GCM/PBKDF2 protects personal data and durable settings; passwords require eight characters minimum. Validate imports and preserve recovery snapshots. Credentials use DPAPI/environment variables, never chat echo or ordinary settings. Never send backup passwords to models.

Expenses shows tokens, USD and categorized spending, receipts and manual entry/correction. Daily token receipts retain independent model calls or historical task entries, grouped by Daily chat, Long-term memory, Self-improvement, Speech understanding, Background work, Development and Speech synthesis. Repeated models are not merged in the daily list. Each row shows model, task/use, time, tokens and cost; small charges retain extra decimals. Daily token-category charts summarize uses. Week/month/year grouping, charts and total calculations retain their established behavior.

SDK tasks retain one billed ledger record with a unique run ID and nested call evidence (model-message IDs, models, tokens, times and tool names, never prompts, responses or tool arguments). Duplicate result deliveries do not add charges. Stable message IDs deduplicate response fragments; SDK turn counts and transport-frame UUIDs are not model-call counts. Complete call evidence can expand a task into daily rows whose costs sum to its total. Per-call costs are explicitly allocated estimates weighted by configured token prices because the SDK supplies task totals. Missing/partial historical evidence stays labeled unknown or incomplete rather than inventing calls or charges. Task titles are resolved locally from evolution points, not copied into the numeric ledger. Original ledger entries are not migrated or rewritten. Mark estimates and sources; sync Claude, ElevenLabs and registered development sessions without double-counting cache/reasoning tokens. `tools/dev_finish.py` records development usage and requests normal restart/completion notices.

## Optional local chat adapter

`src/core/local_llm.py`, called by `chat._local_rag`, implements only Ollama-compatible `/api/chat` HTTP. No model, installer or startup logic is bundled. Add future protocols here, not throughout UI/chat code.

No configuration means no probing, service access or fallback offer. Deploy a service separately and set both `MYN_LOCAL_LLM_URL` (complete HTTP/HTTPS endpoint on a loopback IP, e.g. `http://127.0.0.1:11434/api/chat`, IPv6 `[::1]` allowed) and `MYN_LOCAL_LLM_MODEL` (exact already-installed model, no default/download). Reject hostnames, credentials, queries and fragments. Missing/invalid configuration disables it; clear either variable to disable, and restart after persistent environment changes. Disable proxies and redirects.

Only transient Claude failure during read-only memory Q&A may offer fallback, and the current `consent_local` callback must obtain actual consent. Missing credentials, authentication failures, ordinary chat and local commands cannot enable it. Send question, retrieved evidence, time and preferences only; grant no tools/files/SQL. Require answer, citations and grounded fields and apply source/uncertainty checks. Limit responses to 256 KiB and timeout to 70 seconds; no automatic retry or alternate-model fallback.
